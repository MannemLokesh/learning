10. Bridge Design Pattern in Java
10.1 Introduction
The Bridge Design Pattern is a structural pattern that decouples an abstraction from
its implementation, so the two can vary independently.
10.2 Problem it Solves
You have a hierarchy where one dimension (e.g., abstraction) and another (e.g.,
implementation) grow independently. Without Bridge, this leads to an explosion of subclasses.
10.3 What is Bridge Pattern?
Bridge pattern splits a class into two parts: Abstraction and Implementation, which are
developed independently and combined at runtime.
10.4 Real-World Analogy
A remote control works with various TV brands. The remote is an abstraction, and each TV
is an implementation.
10.5 Structure
package com.mannemlokesh;
//Abstraction
abstract class RemoteControl {
protected Device device;
public RemoteControl(Device device) {
this.device = device;
}
public abstract void togglePower();
}
//Implementation Interface
interface Device {

void turnOff();
boolean isEnabled();
}
10.6 Benefits
• Reduces coupling between abstraction and implementation
• Enables runtime binding
• Makes code easier to extend and maintain

10.8 Examples
Example1: Remote Control and Device
package com.mannemlokesh.example1;
interface Device {
void turnOn();
void turnOff();
boolean isEnabled();
}
class TV implements Device {
private boolean on = false;
public void turnOn() {
on = true;
System.out.println("TV is turned ON");
}
public void turnOff() {
on = false;
System.out.println("TV is turned OFF");
}
public boolean isEnabled() {
return on;
}
}
abstract class RemoteControl {
protected Device device;
public RemoteControl(Device device) {
this.device = device;
}
public abstract void togglePower();
}
class BasicRemote extends RemoteControl {
public BasicRemote(Device device) {
super(device);
}
public void togglePower() {
if (device.isEnabled()) {
device.turnOff();

Example3: Report Formatters
package com.mannemlokesh.example3;
interface Formatter {
String format(String content);
}
class HTMLFormatter implements Formatter {
public String format(String content) {
return "<html><body>" + content + "</body></html>";
}
}
class JSONFormatter implements Formatter {
public String format(String content) {
return "{ \"content\": \"" + content + "\" }";
}
}
abstract class Report {
protected Formatter formatter;
public Report(Formatter formatter) {
this.formatter = formatter;
}
public abstract void display(String content);
}
class FinancialReport extends Report {
public FinancialReport(Formatter formatter) {
super(formatter);
}
public void display(String content) {
System.out.println("Financial Report: " +
formatter.format(content));
}
}

10.9 Bridge vs Other Patterns
Pattern
Purpose
Bridge
Decouple abstraction from implementation
Adapter
Convert one interface to another
Strategy
Change implementation dynamically
Decorator
Add responsibilities without changing class
10.10 Pros and Cons
 Pros
• Abstraction and implementation can evolve independently
• Promotes loose coupling
• Easy to extend in future
󰣗󰣘 Cons
• Adds complexity due to more classes
• Overkill for small hierarchies
10.11 When to Use / Not to Use
Use When:
• You have abstraction and implementation that need to vary independently
• You want to avoid subclass explosion
Avoid When:
• Your class hierarchy is simple and unlikely to grow
