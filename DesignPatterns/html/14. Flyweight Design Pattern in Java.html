14. Flyweight Design Pattern in Java
14.1 Introduction
The Flyweight Design Pattern is a structural pattern used to reduce memory
consumption by sharing common object data instead of duplicating it.
14.2 Problem it Solves
When many objects share common data, creating duplicate instances leads to high memory
usage. Flyweight minimizes memory by reusing existing objects.
14.3 What is Flyweight Pattern?
Flyweight pattern ensures that a class has only one instance per unique state (intrinsic state),
allowing shared use across different contexts (with extrinsic state).
14.4 Real-World Analogy
A font rendering system stores only one object per character style (e.g., Arial 12pt) and reuses
it for every letter drawn.
14.5 Structure
package com.mannemlokesh;
import java.util.HashMap;
import java.util.Map;
interface Flyweight {
void operation(String extrinsicState);
}
class ConcreteFlyweight implements Flyweight {
private final String intrinsicState;
public ConcreteFlyweight(String intrinsicState) {
this.intrinsicState = intrinsicState;
}
public void operation(String extrinsicState) {
System.out.println("Using Intrinsic: " + intrinsicState + ",
Extrinsic: " + extrinsicState);
}
}
public class FlyweightFactory {
private Map<String, Flyweight> pool = new HashMap<>();
public Flyweight getFlyweight(String key) {
if (!pool.containsKey(key)) {
pool.put(key, new ConcreteFlyweight(key));
}
return pool.get(key);
}
}

14.6 Benefits
• Drastically reduces memory footprint
• Improves performance when dealing with large numbers of similar objects
14.7 Implementation Steps
1. Separate intrinsic and extrinsic state
2. Create flyweight objects to store intrinsic state
3. Use a factory to manage flyweight objects
4. Pass extrinsic state at runtime

import java.util.Map;

class CharacterFactory {

characters.putIfAbsent(c, new ConcreteCharacter(c));

}
}

Example3: Database Connection Pooling (Simulation)
package com.mannemlokesh;
import java.util.HashMap;
import java.util.Map;
class DBConnection {
private String dbURL;
public DBConnection(String dbURL) {
this.dbURL = dbURL;
System.out.println("Connecting to: " + dbURL);
}
public void execute(String query) {
System.out.println("Executing: " + query + " on " + dbURL);
}
}
class ConnectionPool {
private static Map<String, DBConnection> pool = new HashMap<>();
public static DBConnection getConnection(String dbURL) {
pool.putIfAbsent(dbURL, new DBConnection(dbURL));
return pool.get(dbURL);
}
}

14.9 Intrinsic vs Extrinsic State
Type
Description
Example
Intrinsic
Shared, stored in Flyweight object
Character symbol, tree type
Extrinsic
Passed from outside at runtime
Font color, tree location
14.10 Flyweight vs Other Patterns
Pattern
Purpose
Flyweight
Reduce memory by sharing common state
Singleton
Ensure one instance globally
Prototype
Clone existing object
Object Pool
Reuse pre-initialized expensive objects
14.11 Pros and Cons
 Pros
• Reduced memory footprint
• Improved performance for repetitive data
󰣗󰣘 Cons
• Increased complexity due to external state
• Need to manage object sharing carefully
14.12 When to Use / Not to Use
Use When:
• You have many objects with shared data
• Memory is a concern (graphics, documents, caching)
Avoid When:
• Objects are highly unique
• Overhead of managing extrinsic state is high
