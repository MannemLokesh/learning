7. Singleton Design Pattern in Java
7.1 Introduction
The Singleton Pattern ensures that a class has only one instance and provides a global
point of access to it.
7.2 Problem it Solves
When only one instance of a class is needed to coordinate actions across a system (e.g.,
configuration manager, logging, caching), creating multiple instances could result in
inconsistency, resource wastage, or conflicts.
7.3 Key Concepts
• Private constructor: Restricts external instantiation
• Static instance: Holds the single instance
• Public accessor method: Provides access to the instance
7.4 Real-World Analogies
• Configuration Manager: You only want one source of truth for application config.
• Printer Spooler: Prevent multiple accesses that could result in corruption.
7.5 Variants of Singleton
Example1: Eager Initialization
package com.mannemlokesh;

}

Example2: Lazy Initialization (Thread-Unsafe)
package com.mannemlokesh;
class LazySingleton {
private static LazySingleton insta nce;

}

Example4: Bill Pugh Singleton (Best Practice)
package com.mannemlokesh;
class BillPughSingleton {
private BillPughSingleton() {
}
private static class HelperHolder {
private static final BillPughSingleton INSTANCE =
new BillPughSingleton();
}
public static BillPughSingleton getInstance() {
return HelperHolder.INSTANCE;
}
}
public class Example4BillPughTest {
public static void main(String[] args) {
BillPughSingleton obj = BillPughSingleton.getInstance();
System.out.println("Bill Pugh Singleton: " + obj);
}
}
Output:
Bill Pugh Singleton: com.mannemlokesh.BillPughSingleton@36baf30c
Example5: Enum Singleton (Serialization Safe)
package com.mannemlokesh;
enum EnumSingleton {
INSTANCE;
public void doSomething() {
System.out.println("Doing work...");
}
}
public class Example5EnumTest {
public static void main(String[] args) {
EnumSingleton.INSTANCE.doSomething();
System.out.println("Enum Singleton: " + EnumSingleton.INSTANCE);
}
}
Output:
Doing work...
Enum Singleton: INSTANCE
