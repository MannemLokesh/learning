3. Simple Factory Design Pattern in Java
3.1 Introduction
The Simple Factory Pattern is a creational design pattern that centralizes object
creation logic in one place. It encapsulates the instantiation of classes and provides a single
point of control to create objects without exposing the instantiation logic to the client.
It is not a part of the official GoF patterns but is widely used in practice.
3.2 Problem Without Factory
public class Client {
public static void main(String[] args) {
Shape shape = new Circle(); // hardcoded
shape.draw();
}
}
Problems:
• Direct dependency on implementation
• Changing shape type means code change and recompilation
3.3 What is Simple Factory?
A simple factory:
• Has a static method to create and return objects
• Takes input to decide which object to create
public class ShapeFactory {
public static Shape createShape(String type) {
return switch (type.toLowerCase()) {
case "circle" -> new Circle();
case "rectangle" -> new Rectangle();
default -> throw new IllegalArgumentException("Unknown shape: " + type);
};
}
}

3.6 Pros and Cons
 Pros:
• Centralized object creation
• Encapsulates logic for instantiation
• Decouples client from concrete classes

󰣗󰣘 Cons:
• Still violates Open/Closed Principle (modifying factory to add new types)
• Becomes bloated if too many types are handled
3.7 When to Use / Not to Use
Use When:
• You need centralized object creation logic
• You expect to reuse creation logic across the app
• You want to hide instantiation details from the client
Avoid When:
• You want to adhere strictly to Open/Closed Principle
• You have too many types or subclasses to manage in one place

The Simple Factory Pattern is ideal for:
• Frameworks
• Libraries with plug-in behaviour
• Simplifying client-side object creation
While not a formal GoF pattern, it is a very practical and frequently used approach in real-
world Java applications.
