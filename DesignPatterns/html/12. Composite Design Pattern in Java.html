12. Composite Design Pattern in Java
12.1 Introduction
The Composite Design Pattern is a structural pattern used to treat individual objects
and compositions of objects uniformly.
12.2 Problem it Solves
When working with tree-like structures, managing objects and groups of objects differently
creates complexity. Composite solves this by treating all elements uniformly.
12.3 What is Decorator Pattern?
It allows you to compose objects into tree structures and work with these structures as if they
were individual objects.
12.4 Real-World Analogy
A directory (folder) can contain files or other directories. You can perform operations like size
or delete uniformly on both files and folders.
12.5 Structure
package com.mannemlokesh;
import java.util.ArrayList;
import java.util.List;
interface Component {
void showDetails();
}
class Leaf implements Component {
public void showDetails() {
System.out.println("Leaf operation");
}
}
class Composite implements Component {
private List<Component> children = new ArrayList<>();
public void add(Component component) {
children.add(component);
}
public void showDetails() {
for (Component child : children) {
child.showDetails();
}
}
}

• Treats single and group objects uniformly

12.8 Examples
Example1: File System (File & Folder)
package com.mannemlokesh;
import java.util.ArrayList;
import java.util.List;
interface FileSystem {
void display(String indent);
}
class File implements FileSystem {
private String name;
public File(String name) {
this.name = name;
}
public void display(String indent) {
System.out.println(indent + "File: " + name);
}
}
class Folder implements FileSystem {
private String name;
private List<FileSystem> contents = new ArrayList<>();
public Folder(String name) {
this.name = name;
}
public void add(FileSystem fileSystem) {
contents.add(fileSystem);
}
public void display(String indent) {
System.out.println(indent + "Folder: " + name);
for (FileSystem item : contents) {
item.display(indent + " ");
}
}
}

12.10 Pros and Cons
 Pros
• Uniform treatment of leaf and composite
• Flexible and scalable structure
󰣗󰣘 Cons
• Can make system overly general
• Might be hard to restrict certain behaviours
12.11 When to Use / Not to Use
Use When:
• You have a tree structure (menu, org chart, file system)
• You want uniform operations on individual and groups
Avoid When:
• You don't need to treat objects uniformly
• You're not working with hierarchies
