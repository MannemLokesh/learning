15. Transaction Management
Transaction management in JDBC ensures that a set of operations on a database is
executed as a single unit. If any operation in the transaction fails, all operations in the
transaction can be rolled back to maintain database integrity. JDBC provides control over
transactions through the java.sql.Connection interface.
If your JDBC Connection is in auto-commit mode, which it is by default, then every SQL
statement is committed to the database upon its completion. That may be fine for simple
applications, but there are three reasons why you may want to turn off the auto-commit and
manage your own transactions −
• To increase performance.
• To maintain the integrity of business processes.
• To use distributed transactions.
Transactions enable you to control if, and when, changes are applied to the database. It treats a
single SQL statement or a group of SQL statements as one logical unit, and if any statement
fails, the whole transaction fails.
To enable manual- transaction support instead of the auto-commit mode that the JDBC driver
uses by default, use the Connection object's setAutoCommit() method. If you pass a boolean
false to setAutoCommit( ), you turn off auto-commit. You can pass a boolean true to turn it
back on again.
For example, if you have a Connection object named conn, code the following to turn off auto-
commit −
connection.setAutoCommit(false);
Key Concepts
1. Transaction:
• A transaction is a sequence of database operations treated as a single unit of work.
• Properties of a transaction are defined by the ACID principles:
o Atomicity: All operations must complete successfully; otherwise, the
transaction is aborted.
o Consistency: The database must transition from one valid state to another.
o Isolation: Transactions must not interfere with each other.
o Durability: Changes made by a committed transaction are permanent.
2. Auto-commit Mode:
• By default, JDBC connections are in auto-commit mode, meaning each SQL
statement is treated as a transaction and is automatically committed.
• This mode can be turned off for managing transactions manually.

15.1 Commit & Rollback
Once you are done with your changes and you want to commit the changes then call commit()
method on connection object as follows −
connection.commit( );
Otherwise, to roll back updates to the database made using the Connection named conn, use
the following code −
connection.rollback( );

15.2 Using Savepoints
The new JDBC 3.0 Savepoint interface gives you the additional transactional control. Most
modern DBMS, support savepoints within their environments such as Oracle's PL/SQL.
When you set a savepoint you define a logical rollback point within a transaction. If an error
occurs past a savepoint, you can use the rollback method to undo either all the changes or only
the changes made after the savepoint.
The Connection object has two new methods that help you manage savepoints −
• setSavepoint(String savepointName) − Defines a new savepoint. It also returns a
Savepoint object.
• releaseSavepoint(Savepoint savepointName) − Deletes a savepoint. Notice that it
requires a Savepoint object as a parameter. This object is usually a savepoint
generated by the setSavepoint() method.
There is one rollback (String savepointName) method, which rolls back work to the specified
savepoint.
